## Repeat the fixture check

```powershell
uv run python -m tests.soak_replay --hours 4 --out recordings/soak-new --keep-rounds
```

Use a new output directory. The runner records source hashes and per-round diagnostics,
and stops on a delivery invariant failure or SEC pacing above eight/second. After five
warmup rounds it also stops for private-memory growth over 256 MiB, task/thread growth
over eight, or Windows handle growth over 128. Missing platform-specific counters are
recorded as unavailable; they are not interpreted as passing measurements. These broad
thresholds catch regressions and do not prove that small or longer-term leaks cannot exist.

`--iterations 1` is a smoke check; it cannot establish hours-long stability or reach the
post-warmup baseline. The shipped runner's one-round smoke completed in 43.18 seconds
with 20 alerts, no delivery/pacing failures and 179 handles. Failure-gate tests independently
exercise delivery loss/duplication, missing body, pacing, memory, task/thread and handle growth.

## Repeat passive sampling on Windows

```powershell
.\scripts\passive-soak.ps1 -Hours 4 -EverySeconds 30 -OutPath recordings\passive-new.jsonl
```

The script only reads counters for the existing bot tree and first-print-owned Chrome.
It logs PID, parent, process name, start time, CPU, working/private bytes, handles and free
RAM. Command lines, cookies, credentials and request headers are not written. It refuses
to overwrite an existing output file. Its completion does not itself grade the counters;
inspect the JSONL for restarts, missing/multiple bots, errors and resource growth.

For a hidden background run, launch the script through a host-approved process mechanism
with hidden-window options. No second bot or synthetic release is needed for passive sampling.
